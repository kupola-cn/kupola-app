目前 `kupola-app` 的前端页面和 mock 业务闭环基本完成，下一阶段应从“功能演示”进入“可运行后台系统”。

**P0：先做**
1. 补齐前后端 API 契约：用户、机构、角色、权限、字典、菜单、审计日志、通知。
2. 后端接入数据库和迁移脚本，移除内存 mock 数据。
3. 前端将用户、机构、权限等 mock store 替换为 API adapter。
4. 实现服务端分页、筛选、排序、批量操作和数据权限。
5. 完善认证安全：密码哈希、JWT 密钥配置、过期时间、刷新/退出、登录限流。
6. 后端统一权限校验，不能只依赖前端 Kupola 权限控制。

**P1：业务完善**
8. 审计日志改为真实记录所有新增、编辑、删除、登录和权限变更操作。
9. 通知消息接入后端，支持分页、已读状态和用户隔离。
10. 用户导入导出改为后端处理，并增加文件大小、字段和权限校验。
11. 统一所有页面的 loading、empty、error、保存失败和网络重试状态。
12. 做移动端、键盘操作、焦点管理和表格大数据量体验巡检。
13. 增加登录、用户、权限、审计和导入导出的 E2E 测试。

**P2：发布准备**
14. 增加环境配置：开发、测试、生产 API 地址和 JWT 配置。
15. 增加 CI：前端构建、后端测试、Kupola 类型检查、E2E 和产物检查。
16. 补充 Kupola 框架最佳实践文档，把当前管理后台作为正式示例。
17. 重新定义前端 `dist` 发布流程，避免源码更新后静态产物遗漏。

建议下一步直接做第 2 项：先确定前后端数据结构和 API 契约，再按用户、机构、权限的顺序接入真实数据。
